# P4 导入事务约束

实现对象：旧 Swift `items.json` 与用户明确选择的 UserDefaults 偏好；不导入旧 Token，不更改旧进程、文件、权限或登录项。
本文件是实现协议，不是正式切换批准或原生验收结论。

- 仅目标 `data.json` 尚未初始化时接受新的导入；旧来源在备份、暂存和每次发布前核验 SHA-256/mtime/大小，macOS 同时预检旧进程已退出。
- `migration-state.json` 是版本化事务日志；`migrations/<UUID>/` 保存源信息、原始任务备份、**白名单**偏好快照、原新版偏好备份及暂存目标。
  不允许日志提供任意目标写入路径，所有目标/备份文件名由代码固定；不可识别的新版本日志保留现场并阻止写入。
- 阶段：Preparing → Ready → Publishing → Committed。发布意图先持久化，随后分别原子发布任务/偏好。
  Preparing 的未完成暂存没有发布权，可安全结束并重新导入；Ready/Publishing 的重试只使用经过校验的同一组暂存文件。
- 只要日志未完成，任务/偏好提交及认证恢复均被阻止。启动恢复先于数据/偏好加载和任何 bootstrap。
  不把半完成的两个文件发布到可编辑 UI；失败不伪报导入成功。
- 目标已发布但完成标记缺失时，以来源、备份和目标哈希核对恢复，禁止重新读取源数据拼接新快照或覆盖用户后续修改。
- 源在过程中变化时停止；可在关闭旧程序并恢复原来源后续传，或显式撤销本次导入再导入新来源。
  若来源已不在但新文件应保留，单独确认“保留当前文件”，不伪称事务完成。
- 取消使用 RollingBack 意图和严格的 before/after 核对，仅撤销本事务仍拥有的文件；恢复原偏好后撤销新任务文件。
  发现未知更改则停止，保留原/新/暂存文件，不强行回滚。
- Committed 后不再用旧快照的哈希约束正常的新编辑；历史迁移记录不能在之后启动时回放旧数据。
  错误事务 ID、已完成事务的重复恢复/保留、目标已初始化时的拒绝导入必须在内存中也幂等：不清撤销历史、不推进会话/同步代次、不重载偏好。
  是否安装已发布文件依据磁盘持久阶段，而不是单看命令是否返回成功；完成标记落盘后的异常也不能留下旧内存权威。
- 日志中的重新登录要求独立于凭据存储，只有一次新的成功认证流程才能解除；不恢复迁移前会话，不因导入后云端为空自动上传无归属任务。
- 坐标按唯一匹配的 NSScreen / Tauri monitor 转换 Cocoa 底部原点 logical points → 顶部原点 physical pixels，再限制到工作区。
  以 Cocoa 主屏顶边确定全局参考，匹配屏幕位置、尺寸和 scale，**不要求名称相同**：锁定的 Tao 使用 `Monitor #<model>`，而 AppKit 使用 localizedName。
  新浮窗宽高按目标屏 scale 计算；恢复路径遍历所有可用工作区，不把副屏坐标夹回当前屏。
  macOS 实际定位传入目标屏还原出的 logical points，避开 Tao 用窗口当前 scale 再解释 physical position 的问题；Windows 使用 physical position。
  匹配歧义、坏坐标或屏幕不可用时记录警告并采用安全默认位置；真实多屏/混合 DPI 仍须原生验收。
  系统通知授权/登录项只重新查询，不从偏好复制，也不自动停用旧登录项。

验证须包含每个阶段的真实进程中断、完整字段读回、来源变化、双文件发布中断、目标被后续修改、磁盘空间/权限/损坏/未知版本、
恢复和撤销幂等、重新登录及旧请求隔离。所有夹具必须位于测试私有目录；不得使用真实用户域或真实凭据作为测试数据。

## 验证与尚未验收的边界

- `cargo test --locked -p doing-desktop migrate::transaction_tests` 覆盖真实协调器、完整字段核对、暂停/恢复/撤销、认证门禁和调用层幂等。
- `killed_migration_processes_recover_and_rollback` 在 20 个准备/发布/完成标记/撤销检查点启动私有子进程，确认到达后终止确切的 owned child；Unix 明确检查退出信号为 SIGKILL。
  后续新协调器从磁盘日志恢复，不借助子进程析构器或内存故障标记；这不是电源故障或 Windows 原生演练。
- 原生 NSDictionary 序列化测试只使用内存合成对象，检查过滤先于备份；不会访问真实 UserDefaults、Keychain 或旧 Token。
- 前端覆盖导入、是否带偏好、撤销/保留二次确认、错误反馈及设置窗口中的恢复入口。实际新应用启动、通知授权、旧 SMAppService 切换、原生多屏和安装态仍另行验收。
